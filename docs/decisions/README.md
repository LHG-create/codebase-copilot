# 技术决策记录（ADR）

本目录记录项目开发过程中的关键技术取舍。每一条都遵循「背景 → 调查 → 决策 → 后果」的结构，
目的是留下**为什么这么做**的完整依据，而不只是「做了什么」。

也包含**被数据推翻的方案**（ADR-005 混合检索、ADR-012 rerank）——
负结果同样是决策依据，而且往往比正结果更有信息量。

## 几条值得单独一提的

- **ADR-005 / ADR-012 / ADR-013：三条「证伪记录」。** 前者否掉混合检索（BM25 对中文是负优化），
  ADR-012 否掉重排序 rerank，ADR-013 否掉语义路由（领域质心）与加权 RRF。
  **保留负结果，是为了避免以后有人（包括自己）再试一遍。**
- **ADR-013 额外记了一条方法论教训**：加权 RRF 在 `top_k=8` 的快速试验里「看起来有效」，
  在 `top_k=4` 的完整评测里却是净负优化（-4.1pp / -2.5pp）。
  **小样本 + 宽松 top_k 上的「有效」，必须用更严的 top_k 复验。**
- **ADR-011 / ADR-012：一条方法论主线 —— 先证明问题在哪，再动手。**
  ADR-011 用「零干扰对照」证明退化来自跨领域干扰；
  ADR-012 先关掉先验证明退化来自先验本身，再用「数据清洗前后对比」
  把 +12.5pp 的功劳拆开，发现**系统贡献是 0**。
- **ADR-012 还记了三个数据管道缺陷**：空壳文档（只有 frontmatter）、
  源码副本过期、评测集污染 —— 三个都不是算法问题，
  而且**只有端到端真机抽查能发现前两个**。
- **一条贯穿始终的提醒**：`alpha` 这类写进配置的魔数，都标注了它是在什么数据上扫出来的。
  ADR-011 扫出的 0.06 在数据修正后就变成了有害参数（ADR-012 决策三）。
- **ADR-014 记了三次「判据本身是错的」**：第一版导语页判据按关键词命中，
  既误伤真内容又漏掉目标；第一版清理脚本按**片段**长度判断，把 AST 切出来的
  短代码片段全判成空壳页；`eval_retrieval.py` 的「线上链路」漏传 `use_domain_route`，
  测出来比线上低 8.3pp。**三次都不是算法问题，都是「测量工具坏了」。**
- **ADR-015 记了一条行为修正**：ADR-013 的澄清在「比较类问题」上是**反效果**的 ——
  收窄到一个领域后，模型只能说「资料里没有另一个框架，无法比较」。
  这类问题不是排序层能解的，只有交互层知道「这是比较题」才能正确处理。
- **ADR-016 记了「界面限制能力」这件事**：流式曾经因为 Streamlit 的 `removeChild`
  崩溃被迫退回整段输出 —— 那不是好不好看的问题，是能力被砍了。
  另外记了两个前端 bug：CSS Grid 的 `min-height:auto` 会把输入框顶出视口、
  移动端自动聚焦会把首屏顶飞（且 `pointer:fine` 判断在移动模拟器上会「假通过」）。
