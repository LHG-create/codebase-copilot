# ADR-015：交互层与服务层 —— 比较类不该澄清、LangGraph 状态图、HTTP 接口、代码 Agent

- 状态：已采纳
- 日期：2026-10-17
- 相关：ADR-013（领域路由与澄清追问）、ADR-014（数据卫生与口径修正）

## 背景

ADR-013 把「领域路由 + 澄清追问」做进了检索链路，但那次只解决了**一个问题里的多个框架**
这一种情况，而且只在 Web 端生效：命令行（`chat_cli.py`）完全没有澄清、多轮、流式；
链路还是线性调用，查不出「这一步为什么这么判」；没有对外的 HTTP 接口；
也不能改代码。这次把这四件事一起补齐。

---

## 决策一：比较类问题不再澄清（修正 ADR-013 的行为）

### 怎么发现的

CLI 接上澄清后第一次实测：

```
你：Spring 和 FastAPI 的依赖注入有什么区别？
⚠️ 这个问题在多个知识域下都有内容，你想问的是哪一个？
  1) FastAPI   2) Spring Framework
请输入序号：1   → 已限定到「FastAPI」

助手：根据已有资料无法回答该问题。
参考资料仅介绍了 FastAPI 的依赖注入系统……完全没有提及 Spring，因此无法对两者进行比较。
```

**澄清把一个本来能答的问题变成了答不了。** 因为比较类问题的答案天然需要**两边**的内容，
把它收窄到单一领域，等于亲手把另一半资料藏起来。

### 决策

`RouteDecision` 增加 `comparison` 字段，命中比较词（`区别` / `差异` / `对比` / `vs` /
`difference` …）时：

- `is_ambiguous` 返回 `False`（不追问）
- `primary` 仍返回 `None`（不收窄到单一领域）

注意这**只影响「要不要追问」**，不改路由本身：只提到一个框架 + 比较词时，
仍会正常限定到那个框架（另一侧不在库里，限定反而是对的）。

### 但「不追问」不够 —— 全库 top-4 仍然只有一边

第一版改完就测，结果还是答不了：

```
问：Spring 和 FastAPI 的依赖注入有什么区别？   （不再追问了，走全局检索）
助手：根据已有资料无法回答该问题。
参考资料仅介绍了 FastAPI 的依赖注入系统……
```

查召回来源，四条**全部**来自 `fastapi/tutorial/dependencies/` ——「依赖注入」这个词在
FastAPI 文档里匹配度最高，Spring 的文档一条都没进 top-4。

**所以比较类问题要做的不是「放开限制」，而是「按域配额取数」**：

```python
# app/retrieval.py
if decision.comparison and len(decision.domains) >= 2:
    return self._balanced_retrieve(question, decision.domains)
    # 每个域各取 max(2, top_k // 域数) 条，合并去重后再截到 top_k
```

改完四条来源变成「FastAPI 2 条 + Spring 2 条」，模型能分别讲清两边的做法：

> **FastAPI**：依赖注入系统设计目标是简单直观，支持层级式依赖（依赖本身可以再定义依赖）…
> **Spring**：团队提倡构造器注入，因为它能让组件成为不可变对象并确保必需依赖不为 null…
> **关于区别**：现有资料分别来自两边文档，没有直接比较的内容，因此无法回答「有什么区别」。

它最后仍然拒绝给出直接对比 —— 这是**有意保留的**。SYSTEM_PROMPT 要求「只能依据参考资料」，
而「归纳出两者差异」已经超出资料原文。检索层的责任是**把料给齐**，不是替模型编结论。

### 这是「交互层」而非「排序层」的典型问题

检索层无法解决它：无论怎么调 RRF 权重、怎么换向量模型，「两边资料都在库里、
但 top-4 只放得下 4 条」这个约束不会消失。只有当系统知道**这是一道比较题**，
才能决定「那就不收窄，两边各给几条」。

## 决策二：用 LangGraph 把链路建成状态图

### 为什么

线性调用（`chain.py`）有两个说不清的地方：

1. **每一步花了多久、做了什么判断，事后无从查证。** 用户说「答得不对」时，
   是路由判错了？检索没召回？还是模型没用上资料？只能靠加 `print` 猜。
2. **「停下来问用户」塞不进线性管道。** 歧义时要中断并等选择，线性写法只能在
   返回值里塞个特殊字段，让调用方自己判断（ADR-013 就是这么干的，能用但不优雅）。

### 图长什么样

```
route ──┬─(歧义)─> clarify ─> END
        └─(明确)─> retrieve ─┬─(无召回)─> END
                             └─(有召回)─> generate ─> END
```

四个节点，两条条件边。每次执行产出 `trace`：

```
route     0.1 ms   限定到 fastapi
retrieve  1776.7 ms 召回 4 条，首条 cors.md
generate  1886.6 ms 生成 992 字
```

这个 trace 直接变成 Web 端的「🔍 执行轨迹」折叠面板，和 `/ask` 响应里的 `trace` 字段。

### 图里**没有**什么（有意为之）

| 没做 | 原因 |
|---|---|
| checkpointer（对话记忆） | 不想出现两套「历史真源」：LangGraph 的 checkpoint 和 Streamlit 的 `session_state` 各存一份，迟早对不上。多轮仍由调用方显式传 `chat_history`。 |
| 循环边（自动重试） | 澄清后不是在图里等，而是返回调用方、用户选完**重新发起**一次带 `forced_domain` 的执行。图保持无环，调试时不会陷进重试循环。 |
| 独立的 Agent 执行器 | 节点就是普通函数，返回 dict。没有隐藏的调度逻辑，出问题一眼能定位。 |

### 怎么保证两条链路不漂移

`chain.py` 保留（评测、CLI、UI 都在用），`graph.py` 是新增入口。两份实现迟早会分叉，
所以约定：**chunk 协议完全一致**（`{"clarification"}` / `{"sources"}` / `{"delta"}`），
任何一端不兼容都会在 CLI / API 上立刻暴露。节点内部复用同一套 `Retriever` 和
`format_docs`，只有控制流不同。

## 决策三：HTTP 接口（`app/api.py`）

四个端点：`GET /health`、`GET /stats`、`POST /ask`、`POST /ask/stream`，
外加 `POST /cases`（案例沉淀）。`http://127.0.0.1:8000/docs` 自动出交互式文档。

### 两个设计上的选择

**1. 澄清返回 200 + `clarification` 字段，不是 4xx。**

「问题需要补充信息」是正常业务流程，不是客户端错误。用 4xx 会逼调用方去区分
「参数写错了」和「我需要再问一句」——这两种情况的处理方式完全不同。

**2. 流式用 SSE，不用 WebSocket。**

问答是单向推送，SSE 浏览器里 `EventSource` 一行接上，还自带断线重连。
事件类型：`clarification` / `sources` / `delta` / `done` / `error`。

### 一个容易忽略的细节

`sources` 要裁剪。检索出来的 `Document` 带完整正文（单片段可达上千字）和一堆内部
元数据，全量返回会让响应体膨胀十几倍，而调用方真正需要的是「出自哪个文件哪几行」。
所以只返回定位信息 + 400 字摘要。

## 决策四：代码修改 Agent（`app/code_agent.py`）

工具只有五个：`list_files` / `grep` / `read_file` / `propose_edit` / `run_tests`。
手写 tool-calling 循环（12 步上限），不用 AgentExecutor。

### 三条安全边界

**1. 写盘是两阶段的。** `plan()` 只产出带 unified diff 的 `FileChange`，**绝不落盘**；
要真正写入必须显式再调 `apply()`。

> 模型给错答案的代价很低，改错你代码的代价很高，两者不该共用同一个开关。

**2. 路径锁在 root 内。** 所有路径先 `resolve()` 再校验 `is_relative_to(root)`，
挡掉 `../../.ssh/id_rsa`；同时硬性禁写 `.env` / `.git/` / `storage/` / `data/`。

**3. 不提供任意命令执行。** `run_tests` 内部拼的是固定的 `pytest` 命令，
模型入参只能是一个测试路径。开放「执行任意 shell」等于把本机控制权交给模型 ——
那已经不是 Agent，是后门。

### 踩到的坑：`lstrip("./")` 会把 `.env` 变成 `env`

路径归一化最初写的是：

```python
normalized = relative.replace("\\", "/").lstrip("./")   # 错
```

`lstrip` 的参数是**字符集合**，不是前缀。`".env"` 开头的 `.` 被吃掉，变成 `env`，
于是禁写正则 `(^|/)\.env(\.|$)` 不匹配，`.env` 就被放行了 —— **安全检查被一行
字符串处理静默绕过**。已改为循环剥掉 `./`，并补了单测 `test_code_agent_rejects_sensitive_writes`
专门盯这个 case。

### 实测一轮（dry-run，未写盘）

任务：「在 `app/config.py` 里给 `api_port` 补一句注释，说明为什么默认端口是 8000」

```
[1] grep(api_port)          → app/api.py:327
[1] list_files(app/*.py)    → 15 个文件
[2] read_file(app/config.py)
[3] grep(8000|uvicorn|port)
[4] read_file(app/api.py)
[8] propose_edit(app/config.py)   +2 / -0
[9] run_tests(tests/)             pytest 通过（37 passed）
结论：只在 api_port 上方加了两行注释，没改任何逻辑。
      依据是 api.py 里写的 --port 8000 和 /docs 地址，属于可验证事实。
```

9 步、只改 1 个文件、测试全通过、diff 可逐行复核。用户选 `n` 后磁盘无任何改动。

## 后果

**好处**

- 四种入口（Web / CLI / HTTP / Agent）能力一致：澄清、多轮、流式全都有。
- 执行过程可观测：每步耗时与判断都留在 `trace` 里。
- 代码 Agent 的权限边界是**可被审计的**（固定 5 个工具 + 路径锁 + 两阶段写盘）。

**代价与遗留**

- **两条链路并存**（`chain.py` / `graph.py`）。chunk 协议一致是人为约定，
  没有自动化的一致性测试兜底 —— 这是真实的技术债。
- **Agent 不做多文件事务**：改 A 成功、改 B 失败会留半成品（有 diff 可回溯，
  但没有自动回滚）。真要上生产应写进临时分支再整体替换。
- **Agent 的 `plan()` 只用 12 步**：任务过宽时会中途停下并如实说明，
  而不是硬着头皮继续改。
- **`/cases` 端点会写磁盘**：它和「Agent 不写盘」是两回事（案例沉淀是用户显式确认的动作），
  但这两件事放在同一个服务里，容易被误认为权限不一致。
