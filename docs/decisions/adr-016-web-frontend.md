# ADR-016：前端不做在 Streamlit 里 —— 零依赖单页 + 同源托管

- 状态：已采纳
- 日期：2026-10-17
- 相关：ADR-015（状态图 / HTTP 接口）、`web/index.html`、`app/api.py`

## 背景

项目最初用 Streamlit（`app_ui.py`）做界面，原因是「一周能把 RAG 跑起来」。
但当功能补齐到「领域路由 + 澄清追问 + 引用溯源 + 状态图轨迹」之后，
Streamlit 的三条硬约束开始直接吃掉产品能力：

1. **重绘模型**：每次交互整页 rerun，组件状态由脚本重新执行决定。
   想在「点击答案里的 `[1]` → 高亮对应出处卡片」这种细粒度交互上做文章，很别扭。
2. **样式天花板**：布局由 `st.sidebar` / 主区 / 展开器这些固定结构决定。
   想要「左知识域统计 / 中对话 / 右检索轨迹」的三栏信息密度，做不到。
3. **流式渲染的历史包袱**：`st.write_stream` 渲染含代码块的 Markdown 时，
   React 在「文本节点 ↔ 代码块节点」之间反复 diff，触发过 `removeChild` 崩溃。
   当时的修法是**退回整段输出**——也就是说，为了稳定，牺牲了流式。

第三条最典型：**它不是「界面不好看」，而是「界面限制了能力」**。
流式是 RAG 体验的核心（首字延迟决定体感），不能一直关着。

## 备选方案

| 方案 | 优点 | 否决原因 |
|---|---|---|
| A. 继续 Streamlit + 自定义 CSS | 改动最小，不用碰新栈 | 组件结构仍是 Streamlit 的；引用联动、轨迹面板、三栏布局都做不了。CSS 只能改皮，改不了骨架 |
| B. React / Vue + Vite | 组件生态成熟，长期可扩展 | 引入 node + 构建链。项目现有承诺是「PyCharm 里点绿三角就能跑」，多一步 `npm install` 就多一类环境问题；而且构建产物对这个小体量并不划算 |
| **C. 原生单页 + FastAPI 同源托管** | 零依赖、零构建、离线可跑；SSE 直接调；完全控制 DOM | 要自己写 Markdown 渲染、SSE 解析、状态管理——一次性成本 |

## 决策

采用 **C**。具体做法：

- **单文件** `web/index.html`：HTML + CSS + JS 全内联，无外链字体、无 CDN、图标全用内联 SVG。
  断网环境下界面不会变样。
- **同源托管**：`app/api.py` 增加 `GET /` 返回该文件。
  这样页面里的 `fetch("/ask/stream")` 不需要任何 CORS 配置，也不需要再起一个静态服务器。
- **SSE 用 `fetch` + `ReadableStream` 手工解析**，不用 `EventSource`：
  后者只支持 GET，而我们的提问必须 POST（问题文本在 body 里）。
- **Markdown 自己渲染**：先 `escape` 再处理，代码块先抽出占位再还原；
  引用角标 `[n]` 变成可点击的 `<span class="cite">`。
  明确只支持子集（标题 / 列表 / 表格 / 引用 / 代码块 / 行内代码 / 粗斜体 / 链接），
  **不支持的就退化成纯文本，不引第三方库**。
- **代码高亮用保守的 tokenizer**：注释 / 字符串 / 数字 / 关键字四类，
  先分词再转义，避免「正则替换破坏 HTML」这类经典 bug。
- **主题用 CSS 变量**，`data-theme` 挂在 `<html>` 上，
  默认跟随 `prefers-color-scheme`，手动切换写 `localStorage`。
- **会话放 `sessionStorage`**：刷新恢复，关标签页即清；不落盘、不上云。
- **深链接 `?q=...`**：把「一次问答」变成可分享的 URL，同时让端到端测试可以直达结果态。

两个刻意的取舍：

- **不做虚拟滚动**。会话量级是「一次几十条消息」，DOM 直接追加足够；
  引入虚拟列表会让「引用跳转 / 展开出处」变复杂，收益不成正比。
- **澄清点选后的重放不重复插入用户气泡**。用户是在补一个约束，不是重复提问；
  界面上重复一条一模一样的问题会让人以为发了两遍。

## 踩到的两个真问题

这两个都不是「审美问题」，值得单独记：

1. **CSS Grid 项默认 `min-height: auto`，会把整行撑出视口。**
   右栏轨迹一长，`.app` 的网格行被撑到 1233px（视口 900），
   表现是「对话一长，输入框被顶到屏幕外」。
   第一反应会去调输入框，但根因在网格：
   `.app{grid-template-rows:minmax(0,1fr)}` + `.sidebar/.main/.inspector{min-height:0}`。
   **截图里「像被裁掉」的东西，往往是布局溢出。**

2. **移动端自动聚焦会顶飞首屏。**
   `#input.focus()` 在 414px 下把内容滚掉 332px，用户还没看到标题就被键盘挡住。
   判断条件不能用 `matchMedia("(pointer: fine)")`——Playwright 的移动视口仍是 fine pointer，
   测试会「通过」而真机有问题。改用 `window.innerWidth >= 880`，语义明确且可测。

## 后果

**收益**

- 流式回到主界面：先出出处、再逐字出答案，可随时停止。
- 三栏的信息密度：知识域分布 / 引擎参数 / 状态图轨迹（每步耗时）同屏可见。
- 引用与出处联动、卡片展开、复制路径、导出 Markdown、深浅主题、移动端抽屉。
- 用户只需要跑 `10. 网页界面 web（含 API）`，打开 `127.0.0.1:8000`，**不需要 node**。

**代价**

- 自己维护 ~1000 行无框架前端：没有组件复用，复杂交互要手写。
- 两套界面并存（Streamlit 保留为「极简备用」），但后者已不再承担主要体验。
- `color-mix()` 需要 Chromium 111+；旧浏览器上徽章背景会退化成透明（不影响可读性）。

**遗留**

- 长会话（>100 条）未做虚拟滚动或分页加载。
- Markdown 不支持嵌套列表、脚注、HTML 内嵌等；遇到会更明显地退化为纯文本。
- 前端只在 Edge / Chromium 上做过端到端验证，未覆盖 Firefox / Safari。

## 验证

- **21 项前端端到端**（Playwright + 系统 Edge，`channel="msedge"`，不下载 Chromium）：
  深链接、流式完成、出处渲染、引用联动、主题持久化、刷新恢复、多轮、
  回到底部、导出 Markdown、澄清重放、移动端抽屉、无 JS 运行时错误。
- **38 项后端离线测试**仍全通过（新增 `path` 字段与 trace 文案改动不影响契约）。
- 5 张界面截图存 `docs/screenshots/`，README 直接引用。
