# ADR-004：用 AST 做代码结构化切分

- 状态：已采纳
- 日期：2026-10-15

## 背景

项目从「文档知识库问答」升级为「代码知识库问答」，需要把 `.py` 文件纳入检索。

## 问题

通用的 `RecursiveCharacterTextSplitter` 按字数切分，会把代码拦腰截断：

- 函数签名和函数体被拆成两段，检索时召回残缺的代码
- 类定义、装饰器、import 与它们的用法失去关联
- 用户问「`foo` 函数怎么实现的」，召回的是「`foo` 函数的上半截 + 另一个函数的下半截」

## 决策

用 Python 标准库 `ast`（抽象语法树）做**结构化切分**：

- 以**函数 / 方法 / 类 / 模块级变量**为最小切分单元，保证每个片段语义完整
- 每个片段把 `签名 + docstring + 代码体` 拼成 `page_content`，签名前置增强检索
- 元数据保留 `kind`（类型）、`name`（符号名）、`start_line`/`end_line`（精确行号）
- 类内部的方法单独拆出，符号名带类前缀（如 `RagAssistant.answer`）

## 后果

- 正向：检索结果是「完整、可定位到具体行号的代码块」，而非「被切碎的文本」。这是本项目区别于通用 RAG 的核心设计。
- 额外收益：元数据里的行号，让答案能精确溯源到「文件:起始行-结束行」。
- 边界：`ast` 只能解析语法完整的 Python 文件；语法错误的文件退化为整文件入一个 chunk（已处理，不中断建库）。
- 教训：**「文档」和「代码」的结构完全不同，切分策略必须分开设计**。这是「针对数据形态选择方案」的判断，而不是无脑套通用工具。
