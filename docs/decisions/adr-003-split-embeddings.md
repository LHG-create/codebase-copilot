# ADR-003：对话模型与向量模型分开配置

- 状态：已采纳
- 日期：2026-10-15

## 背景

RAG 需要两类模型：对话模型（生成答案）和向量模型（把文本转成向量）。

## 问题

很多教程用同一个供应商的同一个 Key 同时做两件事，但这不是普适的：

- **DeepSeek**：便宜、中文强，但**不提供 embedding 接口**，只能做对话
- **通义千问**：对话和向量（`text-embedding-v3`）都有，但对话未必是最优选择

如果强行用一个 Key 配两个模型，要么换供应商时被迫全换，要么根本配不出来。

## 决策

在 `config.py` 里把两者**独立成两组配置**：

```
LLM_PROVIDER / LLM_MODEL          # 对话
EMBEDDING_PROVIDER / EMBEDDING_MODEL  # 向量
```

`llm.py` 里分别提供 `get_chat_model()` 和 `get_embeddings()` 两个工厂。

## 后果

- 正向：任意组合对话模型和向量模型，改 `.env` 一行即可切换，不耦合。
- 代价：配置项从 1 组变 2 组，初看略繁琐，但换来的是灵活性。
- 教训：**「能用」和「好改」是两回事**。把职责拆开，是工程的基本功。
