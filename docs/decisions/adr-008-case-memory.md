# ADR-008：用户问答案例沉淀（RAG 的自我进化闭环）

- 状态：已采纳
- 日期：2026-10-15

## 背景

项目作为「代码知识库」上线后，暴露出一个能力缺口：**它不记得用户问过什么**。

具体来说：
- 用户贴一段错误代码提问，模型给出解答；但下次再问同类问题，一切从头开始。
- 知识库是**静态**的——只能靠 `fetch_docs.py` 重新抓官方文档来更新，
  用户自己踩过的坑、验证过的写法，完全无法沉淀。
- 单次会话内的多轮记忆（`chat_history_msgs`）只存在于浏览器会话里，刷新即失忆。

这带来一个显性的产品局限：系统**不会随使用而变强**。

## 目标

让系统能「记住」用户确认有用的问答，把「使用过程」变成「知识积累过程」——
即 RAG 的自我进化（self-improving RAG）。

## 核心风险：幻觉的自我强化

这是本决策最关键的一点。如果**把模型自动生成的所有答案都写回知识库**，会形成污染闭环：

```
模型答错 → 答案写进知识库 → 下次检索命中这条错答案 → 模型照着错答案回答 → 更错
```

这与之前 `release-notes.md` 污染检索（见 ADR-004 相关工作）是同类问题，但后果严重得多：
前者只是噪声，后者是**系统性错误放大**——系统会越用越错，且用户难以察觉。

因此本功能的设计重点**不是「怎么写回」，而是「写回什么才安全」**。

## 决策

实现**用户确认制**的案例沉淀，四条约束：

1. **只沉淀用户手动确认的内容**。前端「📌 记住这个案例」按钮触发，绝不自动写入。
   让用户（人）承担「这条回答是否可信」的把关职责，从源头切断幻觉污染。

2. **物理隔离 + 元数据标记**。案例独立存放在 `data/cases/`，与官方文档目录分开；
   每条案例元数据带 `origin=user-case`，检索结果可区分「官方文档」与「历史问答」，
   便于排查，也为将来「按来源过滤/加权」留出接口（`app/case_store.py`、`app/loader.py`）。

3. **内容 hash 幂等去重**。文件名含问答内容的 md5 前缀，同一问答重复沉淀会复用同一文件，
   不会堆积重复条目（`save_case()`）。

4. **增量索引，不全量重建**。用 FAISS 的 `add_documents()` + `save_local()` 就近追加；
   检索端持有的是同一个向量库对象，追加后**立即生效**，无需重启或重新建库
   （`app/vectorstore.py::append_documents()`）。

沉淀内容**优先代码案例**：代码是客观事实、可验证，幻觉风险远低于自然语言推理。

## 权衡

- **成本**：每沉淀一条案例 = 1 次 embedding 调用 + 追加落盘（毫秒级），
  相比全量重建（近万片段，约 8 分钟）几乎可忽略。
- **收益**：系统首次具备「越用越强」的能力；这也是简历上的差异化亮点
  （从「静态知识库 RAG」升级为「可自我进化的 RAG」）。
- **代价**：需要用户手动点一下按钮。这是**刻意**的——用一点点摩擦换取知识库的干净。

## 备选方案（已否决）

- **全自动沉淀所有问答**：有体感，但幻觉污染风险不可控，直接否决。
- **对话历史持久化（仅存 SQLite）**：能让「历史还在」，但知识库本身不变，
  系统不会变强，不满足「自主学习」诉求；后续可作为独立功能补充。
- **每次沉淀后全量重建索引**：正确但太慢（8 分钟），交互上不可接受。

## 验证

- 真机端到端：沉淀一条案例 → 索引 `9869 → 9870` → 检索「lifespan 事件」时
  该案例命中**第 1 名**、`origin=user-case` 标记正确；验证后已还原索引，无污染。
- 离线测试（`tests/test_smoke.py`）：新增 4 项——代码块提取、案例幂等写入与元数据标记、
  增量追加使索引增长、`data/cases/` 目录自动打标。全部通过。
